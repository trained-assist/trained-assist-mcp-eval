# Как гонять замеры за $0

Документ появился после того, как замеры выбора MCP-инструмента съели деньги: профиль
`free` оказался не бесплатным. Здесь — что произошло, где именно течёт и что сделать, чтобы
не повторилось. Ничего из перечисленного не сделано, это список задач.

## Что утекло

Один замер — это 2 653 вызова лестницы:

| Шаг | Вызовов | Что это |
|---|---|---|
| `eval-select --tasks tasks/corpus.v1.jsonl` | 1 579 | маршрутизация сгенерированного корпуса |
| `eval-select --tasks tasks/selection.v1.jsonl --runs 2` | 194 | маршрутизация 97 ручных задач, два раза |
| `eval-informativeness` Probe A | 684 | 342 инструмента × (восстановить имя + судить) |
| Probe B | 36 | сопоставление описаний именам |
| Probe C | 160 | маршрутизация в закрытом наборе близких имён |

Локальная сессия 2 октября — ещё около 4 500 вызовов (генерация корпуса, прогоны,
переделки). Плюс восемь запусков CI по расписанию `17 */6 * * *`, то есть **21 224
вызова за три дня без единого участия человека**.

Ответ на все вызовы, включая CI:

```
[eval] models: opencode-go/space-bunny-free×1575, opencode-go/longcat-2.5-preview-free×4
[eval] models: opencode-go/space-bunny-free×193,  opencode-go/longcat-2.5-preview-free×1
```

## Где именно течёт

`src/eval-select.mjs`, `src/eval-informativeness.mjs`, `src/gen-corpus.mjs` — все три
берут профиль из командной строки:

```js
const PROFILE = arg('profile', 'free');
```

Дальше `free` — это алиас лестницы в `trained-assist-llm-ladder`
(`config/ladders.json`), а не обещание бесплатно. Нынешний алиас:

```
opencode-go/space-bunny-free
opencode-go/longcat-2.5-preview-free
openrouter/nvidia/nemotron-3-super-120b-a12b:free
openrouter/inclusionai/ling-3.0-flash-sante:free
openrouter/nvidia/nemotron-3-ultra-550b-a55b:free
openrouter/cohere/north-mini-code:free
openrouter/dots-studio/dots-3-note-preview:free
openrouter/nvidia/nemotron-3-nano-omni-30b-a3b-reasoning:free
opencode-zen/mimo-v2.6-flash-free
opencode-zen/mimo-v2.5-free
opencode-zen/big-pickle
opencode-zen/nemotron-3.5-lightning-free
```

Первые две ступени — `opencode-go/*`, а это подписка OpenCode Go, платная по счёту,
несмотря на `-free` в имени. Лестница падает на них сверху и там и остаётся: 2 652
из 2 653 вызовов ушли именно туда. Слово `free` в названии модели и в алиасе не
означают нулевую цену — единственный надёжный признак нулевой цены у openrouter —
суффикс `:free`.

Два дополнительных факта, которые мешают заметить проблему:

- Ответ лестницы приходит в `data.model`, и `eval-select` уже это агрегирует
  (`byModel`) и печатает строкой `[eval] models:`. То есть детект есть — его просто
  не читали как детект денег.
- `free_100percent` — профиль «восемь бесплатных ступеней, жёсткий потолок $0»,
  описанный в README ладдера, — **в `config/ladders.json` сейчас отсутствует**.
  Лестницу перепинили 4 октября. Полагаться на него нельзя без проверки.

## Что сделать

### 1. Не перегенерировать корпус

`tasks/corpus.v1.jsonl` — 1 579 формулировок — **уже в git** (проверено:
`git ls-files tasks/`). Генерация это ~1 650 вызовов, и её результат детерминирован
по seed. Прогоны ниже используют готовый файл. Генерировать заново имеет смысл
только если каталог инструментов изменился.

### 2. Пинить ступень, а не брать алиас

В ладдере это `ladder_rung` — «pin one rung, no failover» (см. README
`trained-assist-llm-ladder`, строка про `ladder_rung`). Тогда ответ не может уехать
на подписку, потому что альтернатив нет. Практически: брать `openrouter/...:free`
или `opencode-zen/...-free` из списка выше.

Дефолт `--profile` надо поменять на пин, а не на `free`: значение по умолчанию —
это то, что 8 раз задеплоило подписку без спроса.

### 3. Ловить не-бесплатный ответ в коде

Один вызов не должен пройти незамеченным. `callLadder` уже возвращает
`servedModel`; нужен общий белый список и loud-ошибка:

- whitelist вида `/\:free$/` для openrouter и `/-free$/` для zen;
- если `servedModel` не прошёл — исключение, а не запись в отчёт;
- `--profile` со значением, которого нет в whitelist, — отказ на старте, до того
  как потрачен хоть один вызов.

Молчаливый отчёт о 1 579 прогонах, проведённых на подписке, — худший вариант из
возможных: цифры выглядят валидными и ничто не показывает, что заплачено.

### 4. Расписание стоит дороже всего

`schedule: '17 */6 * * *'` в `.github/workflows/ci.yml` — 2 653 вызова каждые шесть
часов без спроса. Между корпусом и CI можно смело поставить сутки. Варианты:

- сузить `cron` до одного запуска в сутки, например `'23 4 * * *'`;
- вынести корпус (1 579 вызовов) из расписания и гонять по `workflow_dispatch`,
  а в расписании оставить только ручной корпус — 194 вызова;
- остановить расписание целиком, пока профиль не запинен.

Третий пункт — тот, который стоит сделать первым: прямо сейчас каждый прогон
продолжает упираться в подписку.

## Что замер уже дал и менять не нужно

Прогон 4 октября 21:25 UTC (модель `opencode-go/space-bunny-free`) против локального
прогона 2 октября — судить о разнице моделей нельзя, но устойчивость вывода видна:

| Метрика | Локально 2 окт | CI 4 окт |
|---|---|---|
| Корпус 1 579 | 66.9% | 64.7% |
| Ручные 97 | 90.2% | 88.7% |
| Probe A | — | 3.05/4, 7 overconfident |
| Probe B | 94.4% | 94.4% |
| Probe C | 81.9%, 2/14 на шансе | 81.3%, 2/14 на шансе |

Разница в 1–2 п.п. — шум провайдера, это уже записано в `README.md` («Baseline»).
Вывод Probe C устоялся: **2 группы на уровне шанса из 14, и те же самые группы** —
`hh_generate_message`/`cold_message_generate` и `hh_candidate_profile`/`demo_candidate_profile`.
Когда алиас будет запинен, выводы из `FINDINGS-corpus.md` и `FINDINGS-confusable.md`
переигрывать не нужно; переигрывать имеет смысл только переименования — их эффект
измеряется тем же корпусом.
